# E5 AI as optimiser (RQ5, protocol §4.5)

Author: beta-f2-4. Descriptive study, no confirmatory endpoint. Tables are generated by `harness/analyze_e5.py` into `results/stats.md`; raw rows are in `results/runs.csv`, `findings.csv` and `steps.csv`.

## 1. Question

Can an AI tool find and fix performance, security and maintainability slop, and how much human control does it need? The runs cross two fixer bundles with two evidence arms and three control levels on one target with a ground-truth list fixed before the runs.

## 2. Design

| item | value |
|---|---|
| target | `e5-optimizer/target`, a small ShelfTap project (package `vn.shelftap.slop`, 8 Kotlin files) built for E5; it is the project in that folder, not an E1 corpus app |
| ground truth | `ground_truth.csv`, fixed before the first run: 14 seeded issues (P01, P04, P06, P07, P08, P10, P13, S01, S03, S04, S05, S06, S07, D01), 3 true-unseeded issues (P03, P11, U05; reported but not scored for recall) and 3 decoys that are correct code and must not be changed (keyed `RecentRow` LazyRow, `Stats()` with remember and derivedStateOf, `BuildConfig.DEBUG`-guarded `Log` in `TokenStore`) |
| fixer bundles | codex = codex-cli 0.170.0 + gpt-5.6-luna; claude = Claude Code 2.1.330 + claude-haiku-5-5 (file tools only). agy (Antigravity 1.5.13 + gemini-3.8-flash-medium) lost authentication (protocol A11), so only descriptive rows exist for it |
| evidence arm | none, or the output of the E1 slop detector run on the work copy, given as text ("it can report false positives and miss problems") |
| control levels | **advice**: read-only, the tool reports findings as JSON (1 human intervention = reading the report); **approve**: one invocation per distinct reported seeded or true-unseeded id (17 steps per sequence), a scripted reviewer accepts a step only if the oracle reports no regression, else the step is reverted; **autonomous**: one invocation, find and fix everything |
| replications | 3 per tool x arm (12 complete sequences for codex and claude, 36 scored rows), run rep-major, at most 2 in flight, shared bench lock |

## 3. Method and judges

Fix quality is judged by `oracle/oracle.py`, a static checker independent of the fixer, never by the fixer's own claims: per seeded issue present, fixed or fixed-with-a-weaker-replacement; regression guards (G1 sources balanced, G7 "cleartext off implies an https base URL", and others); extra weakenings; decoys touched. Every fixed tree is also compiled (`:app:compileDebugKotlin`, `harness/build_check.py`, shared lock and gradle lock; a build that never started counts as infrastructure, not as a failed compile). Reports are scored against the ground truth by (id, file name).

## 5. How much control did the fixer need?

The reviewer in the approve level is a script (the oracle's regression guards), not a person; human group C is out of scope (§13), so the human cost is measured as interventions (advice 1 per run, approve 17 decisions per run, autonomous 0) and the guard is a proxy for a careful reviewer.

| level | seeded issues fixed, codex / claude | final trees with a guard regression | trees compiling, codex / claude | runs touching a decoy |
|---|---|---|---|---|
| advice (nothing edited) | recall 1.00 / 1.00 | 0 | - | 0 |
| approve, step-by-step with a guard | 0.80 / 0.80 | 0 of 12 | 0 of 6 / 5 of 6 | 11 of 12 |
| autonomous | 1.00 / 0.90 | 3 of 12 (all claude, guard G7) | 3 of 6 / 6 of 6 | 10 of 12 |

- The guard did its job on what it checks: the approve loops reverted 10 steps (claude 3, codex 7; 9 on G7 and 1 on G1), and no approve tree ends with a guard failure. Claude's autonomous runs broke G7 in 3 of 6 reps (cleartext switched off while the base URL stays http).
- The price is coverage: a reverted step is not retried, so approve fixes fewer seeded issues than autonomous (0.80 against 1.00 and 0.90).
- A guard that does not run the compiler or look at decoys does not catch the two other failure types: the codex trees that no longer build (all 6 approve trees pass the guard and fail the compile) and changed decoys. Decoys changed in 21 of 24 approve and autonomous runs: `Stats` remember/derivedStateOf in almost all, the `TokenStore` debug-guarded log in all 6 codex autonomous runs and 1 claude run, the keyed `RecentRow` in 4 of 6 codex autonomous and 2 of 6 codex approve runs.
- So on this target advice is reliable enough to hand to a person (every seeded issue found every time, precision 0.82 to 0.94), autonomous codex fixed every seeded issue but changed correct code and broke the build in half the trees, and a per-step approval with static guards reduced the regressions it could see at the cost of coverage. Whether a person reading each diff does better than the scripted reviewer was not tested.

## 7. Defects and deviations

1. **Rate-limit rows scored as outcomes (found and repaired).** The claude cells for reps 2 and 3 (4 sequences, 12 rows) ran while the account's five-hour limit was exhausted: each call returned a `rate_limit_event` with status rejected and 0 tokens in 4 to 6 seconds, and the harness scored them as "nothing fixed" (fixed 0, status ok) and "no parseable report". They were purged (`results/infra_failed_rows.csv` keeps the 12 original rows), `run_e5.py` now detects a rejected rate-limit event, purges the sequence and waits 20 minutes, and the four sequences were re-run (`--redo`) after the limit reset. The numbers above include only the re-run.
2. **File-system errors.** The repo volume returned intermittent ENOSPC (NTFS file records, not disk fill). Retry layers were added; a sequence that dies on a file-system error is purged and redone (`File exists ... snap1` after a crash was handled that way), and a gradle build that never started is infrastructure, not a compile failure.
3. **Judges.** Protocol §4.5 asks for fix success judged by the independent test suite and E2 metrics. The target has no test suite and no E2 measurements were taken on the fixed trees; the judges are the static oracle and the compile gate. A fixed tree that compiles and passes the guards is not shown to behave or perform the same.
4. **Reviewer.** Approve-with-approval is run by a scripted reviewer, not a person.
5. **Agy.** Dropped as a fixer after the authentication loss (A11); descriptive rows only.
6. **Generator independence.** The target is not AI-generated by these bundles, so the "fixer differs from generator" condition is met trivially.

## 8. Threats to validity

One small target with 14 seeded issues that the taxonomy in the prompt names; the advice ceiling says the task is easy once the taxonomy is given, not that the tools find unseeded slop. Two bundles, 3 reps. The oracle is regex and structure based; `fixed` means the pattern is gone and the guards hold. The decoy list is three items. The evidence arm uses the E1 detector.
